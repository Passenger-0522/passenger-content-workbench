# 交给 Antigravity 的实施提示词

将下面整段交给正在开发网站的 Antigravity。配套文档位于同一目录；若项目移到另一台电脑，先复制整个文档目录，再替换路径。以本稿及 PRD v1.2 为准。

```text
继续建设我现有的本地个人自媒体工作台。请先完整阅读以下文档：

/Users/liangxiaoling/Documents/Playground/output/self-media-workbench-2026-10-10/需求确认.md
/Users/liangxiaoling/Documents/Playground/output/self-media-workbench-2026-10-10/PRD.md
/Users/liangxiaoling/Documents/Playground/output/self-media-workbench-2026-10-10/Skill清单与多工具协作.md
/Users/liangxiaoling/Documents/Playground/output/self-media-workbench-2026-10-10/日常流程与对标拆解.md

按以下原则实施：

一、先核验当前项目，保留已有成果。
确认当前项目目录、技术栈、已有页面、后端、存储、素材和可用功能。
区分真实功能、仅界面、待配置与失败，不把另一个历史项目当成当前项目。
沿用适合的实现，不覆盖我的内容或凭据，不从头另建一套相互冲突的数据。
日常实现选择由你判断，只有影响既定范围且文档无法解答的问题再集中问我。

二、网站定位与使用方式。
未来 90 天优先扩大 AI 内容曝光和粉丝量、积累商单机会。
保留跨境电商 / 亚马逊 + AI 内容线，以及商单、咨询、陪跑、平台激励的独立记录。
网站本机运行，用于编辑、预览、归档、计划、复制和导出；第一版由我手动发布。
“一键分发”是生成所选平台的发布包，不代表自动登录或公开发布。
创作可在 Antigravity 或 Codex 聊天，不强制网站内置另一个聊天模型。

三、模型与工具分工。
全部平台文案和视频脚本默认由 Antigravity / Gemini 完成，包括 X。
Gemini 不需要预写封面标题或图内文字，基本产物是正文。
需要封面时，Codex 直接读取正文，自行提炼封面表达和生成图片；不新增正文不支持的事实。
平台必要发布标题允许后续补齐，不作为想法入库的前置条件。
AI 图片与封面优先交给 Codex 原生生图，公众号排版可使用本地脚本或 Codex。
Antigravity 是开发入口，不是网站唯一的模型来源。
写作、作图、排版分别建任务，标明执行方；不要让作图任务再重写我认可的正文。
确认后的正文与已确认发布字段受保护；Codex 可以生成独立视觉文字，用户指定准确文字时才作为硬约束。
需要改字时提出建议，接受后再产生新修订，并标记受影响图片待更新。

四、订阅优先。
优先通过官方客户端 / 官方 CLI 的订阅登录执行，不用反代，不提取登录令牌构造 API。
第一版先支持两个客户端的本地文件交接，不以 CLI 全自动执行或购买模型 API 为前提。
模型 API 默认关闭，即使本机存在 key 也不能自动使用。
额度不足时暂停并保留任务，禁止自动购买额度、开启超额付费或切换付费 API。
TikHub 数据服务与模型订阅分开显示，不编造剩余额度。
模型名称是偏好，实际可选模型由客户端核验；不能承诺 Codex 原生工具固定指定 image2.5。

五、完整交接协议。
在 Antigravity 中建立项目级捕获规则 / workbench-capture 约定：
我在对话框提交今天的想法、正文或收藏链接时，你保存原始输入并生成捕获包。
不要求我先打开网站建项目，不要求再次手动粘贴，缺标题 / 平台时也能存为待整理想法。
网站后台自动监听完整捕获包，补偿漏事件，入库后返回真实回执。
只有收到回执才能告诉我已保存到网站；服务不在线时明确标为待导入。
网站导出带 projectId、variantId、taskId、baseRevision、来源、已确认文字、产物要求的任务。
外部工具写入独立 incoming 包，包含 manifest、真实文件和最后写入的 READY 标记。
网站校验后导入，支持 ZIP / 目录手动导入兜底。
按 schemaVersion 和 importId 幂等，拒绝路径穿越，检查文件存在与素材引用。
旧版本导入展示冲突；图像与排版任务只能更新允许字段，不能静默覆盖正文。
不要让外部工具直接随意改数据库。
补齐发布包必须以真实图片 / 视频 / HTML 文件为依据；仅提示词不算图片。

六、内容与平台。
母稿、平台版本、素材资产、真实发布记录分开建模。
平台和形式分开：X 短帖 / 引用 / 转推 / Thread / 长文，小红书图文 / 视频，公众号文章 / 贴图，抖音及视频号图片组合 / 视频。
支持一个项目选部分平台，不要求每个选题发所有平台。
各平台版本有独立文案、素材、封面和历史；图文页文字与发布页正文分别保存。
支持视频号至少两个封面用途，但具体比例待核验，不随意预填官方尺寸。
小红书 3:4 和公众号 2010×600 属于当前制作约定，按文档记录依据与可配置状态。

七、Skills。
读取 Skill 清单中的真实文件和相对引用资源，先检查依赖，再按任务需要注册。
Skill 是流程说明，不等于网站已经能调用模型或自动生图。
优先复用 content-publishing-os、imagegen、gzh-design、punk-cover、baoyu-xhs-images。
xhs-note-creator 本地模板渲染和 AI 生图是不同路线，可配置选择。
其余封面风格与文案诊断按需启用，不默认串行执行所有 Skill。
链接采集可复用 defuddle；可选 Obsidian 留档遵守 obsidian-personal-database-ops 和真实 Vault 规则。
workbench-capture 与 content-deconstruction 是需要按本稿实现的任务流程，不冒充已经安装。
imagegen 的 API 备用脚本默认禁用；Codex 原生工具与该脚本区分。
不注册 Skill 自带的自动公开发布或账号操作脚本。

八、搜索与每日工作。
供应商采用 TikHub；先核验其 X 与抖音搜索，再接可选的小红书 / TikTok 素材搜索。
未配置 key 时准确显示待配置，保留手动链接 / 文件导入。
不使用模拟数据冒充真实搜索。保存来源 URL、作者、时间、抓取时间和请求状态。
完整第一版包含后台每日检索、去重、候选、请求限额、有限补跑和失败记录。
网页关闭后后台可运行，但不能承诺关机或睡眠期间执行。
写作 / 生图的 CLI 自动执行未验收时，只生成交接任务，等待外部产物。

九、每日目标与计数。
X 每天约 10～15 条，原创短帖、引用转推 / 转推分别统计，偶尔长文。
小红书、公众号、抖音、视频号初始按各平台每天 1～2 条，可修改。
准备、复制、下载、排期不增加真实发布数；只有用户确认发布才计数。
Thread 同时展示内容单元数与串内帖子数，口径可配置。
首页显示目标、已发布、已准备、缺口与当天需要我处理的任务。
按平台列出今日待发、逾期未发、未排期的可发布版本与制作中内容。
选题单独显示待判断、已选待做、制作中、已做、暂缓、不做；已做不等于已发布。
没有效果数据时显示未录入，不拿未知曝光或收益当 0。

十、本地可靠性与边界。
使用本地持久化数据库和文件资产，不以 localStorage 作为内容唯一存储。
提供备份 / 恢复、版本冲突、导出失败、缺依赖、网络错误和日志摘要。
只运行预登记的官方 CLI / 本地脚本，使用结构化参数，不拼接任意 shell。
密钥不写入正文、导出包、前端或普通日志，不复制登录缓存。
不打开 / 操作紫鸟或任何 Amazon 账号页面；Amazon API 仅可按已有授权只读。
不自动联系商单方或其他人。

十一、对标研究和文章资料。
管理小红书、抖音、视频号、公众号、X 的对标博主和账号。
保存各平台粉丝快照的原始值、精确 / 约数、观察时间、采集来源与错误，不相加为去重总粉丝。
没有可靠自动数据时支持手动录入 / 导入，未知不填 0，采集失败不清空历史。
链接收藏保存原 URL、规范 ID、作者、时间、原件 / 正文 Markdown 与采集完整性；仅链接不冒充全文下载。
文章拆解与账号拆解由 Gemini 执行，引用真实段落 / 样本、标明覆盖，给出值得对标的理由与可以转成选题的动作。
账号注册时间、真实起号日期、最早样本发文时间分别记录，不从有限样本伪造起号历史。
拆解建议转选题，再决定制作顺序、平台适配与排期，不自动搬运或批量改写外部文章。
发布时段以可用时段 / 真实历史数据提出试验建议，不宣称固定最佳时间。
网站是状态与关系的权威；Obsidian 先支持 Markdown 导出，再按真实 Vault 契约单向留档。
不让 Obsidian 编辑自动覆盖网站正文或修改发布 / 粉丝状态。

十二、记录后续草稿箱投递。
将“投递各平台草稿箱，用户检查后发布”作为 P2 路线保留，不在本轮擅自开通或写入远端账号。
将发布包、远端草稿、公开发布分开建模；草稿投递成功不增加已发布数。
未来逐平台核验接口 / 主体资格 / 权限 / 媒体上传 / 回读，不承诺全平台统一草稿 API。

实施顺序：
1. 当前项目审计和差距清单。
2. Antigravity 对话想法自动入库与真实回执 → 待做选题 → Gemini 正文 → Codex 直接读正文做图 → X / 小红书发布包 → 用户确认发布 → 今日计数。
3. 公众号排版、贴图、视频、多用途封面、有序图片与本地组合视频、备份恢复。
4. 真实 TikHub 搜索与每日后台调度。
5. 对标账号、粉丝快照、链接采集、文章 / 有限样本账号拆解、报告转选题，接入效果与线索记录。
6. 下一阶段增加官方 CLI 执行适配器，写作、原生生图、排版逐项验证。

按 PRD 验收场景完成验证。每阶段报告已完成、待配置、部分完成、失败及证据。
区分结构校验、视觉校验、真实目标编辑器粘贴和用户公开发布；不以截图代替功能验收。
第一版必需功能未验收时，明确剩余内容，不称为完整交付。
```

本提示词授权本地开发与验证既定功能。新启用付费模型执行路线、自动公开发布或改变 Amazon 远端资源不在其范围内。
