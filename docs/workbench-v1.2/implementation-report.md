### 1.2 Codex Round 3 深度门禁 6 项检查验证

针对 Codex Round 3 审查（`docs/workbench-v1.2/Codex-round3-review.md`）指出的 6 项深层安全性与完整性问题，已全部修复并通过专用测试脚本（`scripts/test-codex-round3-deep.py`）严密验证：

1. **DNS 重新绑定攻击 (Host Header) 拦截**: 
   - 修正前：`(!isLoopbackHost && !isLoopbackAddress(remoteIp))` 存在逻辑穿透漏洞。
   - 修正后：全局中间件与 `/api/auth/token` 握手严格要求 Socket IP 为环回地址 **且** Host 标头匹配环回正则（`^(127\.0\.0\.1|localhost|\[::1\])(:\d+)?$`）。非环回 Host（如 `fixture-rebind.invalid`）一律返回 **HTTP 403 Forbidden**。
2. **软链接目录逃逸 (Symlink Escape) 防御**:
   - 修正后：在 `/api/assets/incoming`、`/api/assets/synthesized` 及外部导入解包过程中，采用 `fs.realpathSync` 严格比对真实物理绝对路径，凡逃逸出对应资源根目录的软链接一律阻断并返回 **HTTP 403 Forbidden**。
3. **截断 / 伪造图片全量二进制校验**:
   - 修正前：仅读取 PNG 文件头部 IHDR，未校验后续数据块与尾部。
   - 修正后：在文件尺寸基线检查（`size >= 68`）基础上，优先调用本地 FFmpeg 引擎执行全帧硬解码探测（`ffmpeg -v error -i <file> -f null -`）；无 FFmpeg 时核验 PNG 数据块 `IDAT` 与结束标记 `IEND`、JPEG 尾部 `0xFF 0xD9`。截断或伪造图片被百分之百识别并拒绝。
4. **全无效图片导入包拒绝回执**:
   - 修正后：交接包若声明包含图片素材但实际无一张有效落盘，回执状态直接标定为 `failed`，绝不回写有效项目资产或冒充 `imported` 成功。
5. **图文变体齐套性与发布前就绪校验**:
   - 修正后：在 `PATCH /api/projects/:id/variants/:variantId` 中，针对 `image_text` 图文变体，若关联有效封面/图片数为 0，拒绝将状态修改为 `ready`，返回 **HTTP 400 Bad Request** 并明确指示缺失素材清单 `missing: ['covers']`。
6. **今日发布合集包导出端点**:
   - 修正后：实现了 `GET /api/export/today`，支持按日期输出带有 YAML Frontmatter 元数据的高可读性 Markdown 归档包或结构化 JSON，首页合集包下载按钮不再返回 404。

## 2. 核心架构与安全边界实现

### 2.1 网络与接口安全边界
- **Loopback-Only 监听**: 服务端在 `server/index.ts` 中通过 `app.listen(PORT, '127.0.0.1')` 严格绑定到本地环回接口，杜绝局域网或公网外部访问。
- **全局 Origin 与 Host 检查**: 请求必须来源于受信任的本地地址（`localhost` 或 `127.0.0.1`）。跨域预检与写操作响应携带 `x-workbench-token` 鉴权头。
- **写操作密码学安全鉴权**: 启动时生成 256 位安全随机密钥（`LOCAL_SESSION_TOKEN`），所有写操作路由（`POST`, `PATCH`, `PUT`, `DELETE`）通过 `crypto.timingSafeEqual` 进行恒定时间比对，彻底杜绝字符串比较可能引发的时序侧信道攻击与绕过。前端 `src/api.ts` 与外部交接脚本 `scripts/capture.sh` 通过环回握手自动获取并挂载此 Token。
- **凭据掩码与零账单防护**: 
  - `GET /api/settings` 对 `tikhubApiKey` 等敏感配置进行掩码脱敏（仅显示末尾 4 位字符），绝不明文传输。
  - 环境变量默认锁定 `ENABLE_MODEL_API=false`，严禁任何自动化脚本发起付费模型调用或反向代理计费。
  - 严禁任何打开紫鸟浏览器、操作 Amazon 账号或向远程社交平台自动提交草稿的操作。

### 2.2 数据持久化与隔离模式
- **持久化存储结构**: 所有真实生产数据持久化保存在本地工作区 `data/` 目录中：
  - `projects.json`: 完整项目、母本文案修订历史、平台变体定义、卡片文字与关联封面。
  - `topics.json`: 选题库、灵感来源、思路大纲及关联项目状态。
  - `sources.json`: 抓取文章原文素材、可读性状态（full/partial/link_only）、段落拆解报告。
  - `leads.json`: 商业变现线索、高客单咨询、教练陪伴及平台激励记录。
  - `receipts/`: 外部工具导入真实回执与冲突记录。
  - `incoming/`: 外部交接包临时接收目录。
  - `media/synthesized/`: 本地图片组合生成的 MP4 视频与素材。
  - `backups/`: 全量快照与媒体备份目录。
- **隔离环境支持 (`WORKBENCH_DATA_DIR`)**: 服务端完全支持通过环境变量覆盖数据根路径。验收测试套件运行于 `/tmp/workbench-e2e-isolated-data`，全流程测试未污染任何用户的真实文案、历史笔记或对标账号。

## 3. 双客户端分工与文案保护体系

PRD v1.2 明确规定了 Antigravity 与 Codex 在本机上的协同规则：**Antigravity 主管文案策划与去 AI 味润色；Codex 主管视觉设计、原生生图与视频制作**。

```
[Antigravity / Gemini 写作] ──> 母稿文案 (MasterDraft Rev N) ──> 锁定保护 (Locked)
                                         │
                                         ▼
                               [Codex 读取正文产出图片]
                                         │
                   ┌─────────────────────┴─────────────────────┐
                   ▼                                           ▼
      [合规作图包导入: cover.png]                  [作图任务试图改动正文]
                   │                                           │
                   ▼                                           ▼
          挂载到对应平台变体封面                        严格拒绝回写 (Rejected)
       正文保持独立锁定状态未被修改                     母稿与变体正文完整保留
```

### 3.1 锁定正文拒绝回写 (UC-27)
- 用户确认正文后，可通过 `POST /api/projects/:id/lock` 将当前母稿修订置为锁定状态（`locked: true`）。
- 当 Codex 作图交接包试图在 `manifest.json` 中附带 `copy` 文件回写时，导入服务在 `server/services/handoff.ts` 中严格拦截，记录告警：`"拒绝外部任务修改正文：正文已被锁定保护"`，文案修订保持不变。

### 3.2 覆盖冲突与历史追溯 (UC-4)
- 若网站人工修改正文生成 Rev 2，而外部工具离线基于 Rev 1 生成新文案导入，系统通过 `manifest.baseRevision` 识别版本脱节，自动触发冲突保护：
  - 外部文案不静默覆盖网站当前内容；
  - 生成 `conflict_preserved` 状态回执，保存双方文本差异与告警说明；
  - 网站当前 Rev 2 正文完整保留。

### 3.3 正文与卡片文字完全解耦 (UC-7)
- 小红书等多页图文变体的 `cardTexts`（每页大字卡片文字）与发布正文 `content` 物理分离。
- 编辑或更新单页图片卡片文字时，发布页正文不会被篡改；反之亦然。

## 4. 平台发布包与媒体渲染能力

### 4.1 五大平台独立变体与纯净导出 (UC-5, UC-6, UC-8, UC-10)
系统支持为同一内容项目创建五大主流平台的独立发布变体，支持图文与视频并存：
1. **微信公众号 (`gzh`)**:
   - `GET /api/projects/:id/variants/:variantId` 返回纯净正文 HTML 与段落样式，过滤任何无关 UI 按钮。
   - 提供有序图片兜底标记，应对外部编辑器不保留外链图的场景（UC-9）。
2. **小红书 (`xiaohongshu`)**:
   - 支持图文版（3:4 比例卡片、标签体系）与视频版独立存储，互不覆盖。
3. **微信视频号 (`channels`) 与抖音 (`douyin`)**:
   - 视频号支持双封面用途（UC-11）：竖屏封面（9:16，`channels_vertical`）与横屏封面（16:9，`channels_horizontal`）分别管理独立预览与原图下载。
   - 基础视频文件支持跨平台共享复用。
4. **X (推特) (`x`)**:
   - 支持单帖短文与 Thread 长串（UC-16）。在统计口径上严格区分「1 个内容单元」与「串内 N 条推文」，杜绝口径混淆。

### 4.2 本地视频运行器与静音合成 (UC-12, UC-13)
- 服务端集成本地 FFmpeg 探测器（`/Users/liangxiaoling/Documents/Playground/bin/ffmpeg`，版本 9.0.1）。
- 接口 `/api/media/image-combo` 支持将多张有序封面图片合成为可播放的 MP4 视频（1080x1440 统一基准画幅）。
- 在未提供音频文件时，合成服务输出静音视频并明确返回 `isSilent: true, hasMusic: false`，杜绝虚假配乐。

### 4.3 真实发布确认与 KPI 统计 (UC-14, UC-15, UC-34)
- **严格确认模型**: 生成物料、复制文案或下载图片 **绝不自增发布计数**。
- 用户在平台实际发布并点击「确认真实发布」（`POST /api/publish/confirm`）后，今日发布计数方加一。
- 同一变体重复调用确认发布具备幂等性保护，发布计数不重复递增。
- 看板流水线严格区分「待做选题（toDoTopics）」、「待发变体（readyToPublish）」与「已发记录（published）」，部分平台发布不隐藏其他平台的待发变体。

## 5. 采集、对标与知识沉淀闭环

### 5.1 原文收藏与文章拆解 (UC-37, UC-38)
- 收藏网页或公众号文章时，仅提供 URL 则标定为 `link_only`；抓取全文后进入 `full` 状态。相同 URL 提交幂等去重（`canonicalId` 去重）。
- 针对具有全文的素材，支持生成结构化拆解报告（受众、开头钩子、行文结构、论据证据、节奏要点、结尾行动点），并可一键将拆解成果转化为新选题（`POST /api/sources/:id/convert-to-topic`），形成选题闭环。
- 严禁空正文素材自动标记为已拆解，杜绝占位报告。

### 5.2 对标账号与真实粉丝快照 (UC-22, UC-35, UC-36, UC-39)
- 支持小红书、抖音、X、微信视频号、公众号对标博主独立建档。同名不同平台博主独立保存，不自动合并。
- 粉丝数支持录入约数（如“3.7万”自动解析为 37000，并保留 `precision: 'approximate'` 标记）；未录入时保持 `precision: 'unknown'`，未知数据绝不填 0。
- 账号时间线依据有限样本标注样本区间（如“近3个月精选10条爆款”），绝不将有限样本最早日期篡改为确定起号日期。

### 5.3 商业收益与线索追踪 (UC-23)
- `LeadStudio` 模块支持记录商单（commercial_order）、企业咨询（consulting）、个人教练（coaching）与平台激励（platform_incentive）。
- 收益金额支持明确标注「待定 / 未知」，未确定金额不强制记为 0 元。
- 线索属于本地私密笔记，杜绝任何外部自动联系行为。

### 5.4 知识单向导出与备份恢复 (UC-24, UC-40)
- `GET /api/export/markdown?projectId=:id` 提供标准的 Markdown 单向导出，附带规范的 YAML Frontmatter 元数据。导出操作不影响发布状态与 KPI 统计。
- `POST /api/backup` 与 `POST /api/restore` 实现全量数据与静态媒体素材（图片、合成视频）的快照式备份与干净目录还原，跨恢复验证项目、正文与媒体完全一致。
