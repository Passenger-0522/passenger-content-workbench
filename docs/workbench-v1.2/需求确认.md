# 个人自媒体工作台：需求确认

日期：2026-10-10（Asia/Shanghai）

## 本轮已确认

1. 未来 90 天主目标：扩大 AI 内容曝光和粉丝量，积累商单机会。
2. 第一版分发：生成各平台发布包，用户复制文案、下载图片和视频并手动发布。
3. 主要创作入口：在 Antigravity / Codex 等工具里聊天，让产物进入本地网站；网站负责编辑、预览和导出。
4. X 的每日目标由原创短帖、引用转推 / 转推组成，偶尔长文；分别统计类型。
5. 搜索供应商为 TikHub：https://tikhub.io/；本轮不需要用户提供密钥。
6. 全部平台文案（包括 X）默认由 Antigravity / Gemini 完成；图片、封面优先由 Codex 原生生图完成。
7. 模型执行优先使用订阅额度，不希望反代，不以购买模型 API 为第一版前提。
8. 需要列出本机已有封面、公众号排版和相关内容 Skill 的真实路径与接入条件。
9. Gemini 不必提前写封面标题 / 图内文字；需要封面时 Codex 直接读取正文，自行提炼视觉表达并生成图片。用户指定的准确文字才作为硬约束。
10. 用户在 Antigravity 对话框提交当天想法、正文或收藏链接，自动入库到网站；不要求再手动粘贴。
11. 首页展示今日未发 / 待发、制作中内容，选题区区分已做 / 未做；创作完成与发布完成分开。
12. 管理小红书、抖音、视频号、公众号、X 的对标博主，按平台保存粉丝数据与历史快照。
13. 收藏文章链接、保存可读原文、标记对标文章；支持文章 / 博主拆解，衔接新选题、制作与发布计划。
14. 记录后续想法：将成品投递平台草稿箱，用户在平台检查并发布；当前不执行远端投递或自动公开发布。

## 用户原始要求

- 本地、个人使用的自媒体工作台。
- 支持从选题、想法、外部帖子、图片、视频进入内容项目。
- X：想法、转推、长文；每天约 10～15 条。
- 小红书：图文（标题、正文、图片）；视频另配封面，暂用 3:4。
- 公众号：文章（标题、正文、摘要、排版、图片、封面）与贴图 / 小绿书两种形式。
- 抖音与视频号：图片组合加音乐，默认不另做封面；视频需要各自适配的封面。
- 视频号可能有两个封面展示用途，需要核验并支持多个封面变体。
- 小红书、公众号、抖音、视频号：每天约 1～2 条；需要将目标配置化，并进一步确认平台 / 形式的计数口径。
- 每日搜索内容，用户可配置数据服务的 API 凭据。
- 保留不同平台的内容定位；跨境电商和亚马逊 + AI 真实实践可为内容提供依据与辨识度。
- 咨询、陪跑、平台激励与商单属于不同收益来源，分别记录，不预设已开通资格或可获取收入。

## 实施时核验

- TikHub 的实际凭据、接口响应、余额与限额。
- 当前 Antigravity 项目的目录与现有能力。
- 视频号封面展示用途与规格。
- 图像 / 视频运行器，以及真实编辑器粘贴效果。
- 官方 CLI 订阅任务路线的实际可用性、模型选择与图片落盘能力。
- 各平台对标账号资料 / 粉丝数接口；公众号与视频号未确认自动覆盖。
- 文章完整正文、媒体采集与有限样本账号内容覆盖。
- 真实 Obsidian Vault 的规则与导出启用范围；本轮不向 Vault 写入。
- 后续草稿投递能力、账号权限、媒体上传与远端回读。

## PRD 中须明确的边界

- 素材、内容母稿、平台版本、发布记录是不同对象。
- 本地生成、复制、下载、排期均不等于实际发布。
- 允许一个选题选择部分平台，不强制全平台分发。
- 网站不能仅靠读取 SKILL.md 就自动拥有模型、作图或视频能力；需要实际运行器或接收外部产物。
- 视频号封面规格尚未核验，不能作为已确认的官方尺寸写死。
- 每日任务依赖本地进程运行及网络；关机或睡眠期间不能保证执行。
- Gemini 与 Codex 通过本地文件和项目 ID 协作，不要求只在 Antigravity 聊天。
- 正文与 Codex 生成的视觉文字分开保存；作图与排版不能静默重写正文，不要求 Gemini 预写封面文字。
- 订阅限流后等待或转人工，不自动使用付费模型 API；TikHub 数据服务单独计费。
- 网站状态 / 数据库为权威；Obsidian 作为可选长期资料出口，初期单向导出。
- 未知粉丝数不填 0，约数保持标记；样本中最早文章不当作确定起号日期。
- 草稿投递与公开发布分别建模，投递成功不计入已发布。
- 不操作 Amazon 账号页面或紫鸟；Amazon API 只读规则照常适用。
