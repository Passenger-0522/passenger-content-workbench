## 一、 核心实施项落地清单 (按照 Codex Round 5 评审逐条闭环)

### 1. 视频号双封面规范与偏差预警 (PRD Case 11)
- **双命名用途**: 明确提供「竖屏视频主封面 (`channels_vertical` / 9:16 / 1080×1920)」与「横屏动态分享卡片封面 (`channels_horizontal` / 16:9 / 1920×1080)」。
- **可编辑推荐规格**: 用户可随时在界面上调整目标推荐宽高（如 1086×1448、1672×941 等），界面明确提示“推荐参考尺寸，非平台硬编码限制”。
- **角色分配与就近匹配**: 支持通过下拉框将具体上传素材指定给对应封面角色，未指定时按长宽比数值差绝对值就近匹配（非脆弱的字符串全等）。
- **长宽比偏差预警**: 当素材实际长宽比与目标推荐比例偏差超过 8% 时，界面即时显示黄色告警标识（如偏差 33%，不阻断流程，辅助人工复核）。
- **独立预览与下载**: 竖版与横版双封面支持各自独立的缩略预览、原图尺寸查看与一键下载。

### 2. 多页卡片文案分离、排序持久化与静音 MP4 本地合成 (PRD Case 7, 12, 13)
- **单页独立文案与正文分离**: 每张卡片拥有专属独立文案输入区（存储于 `cardPageTexts[coverId]`），不污染发布母稿正文；输入框去除默认回退到提示词的逻辑，避免把“用户本地上传真实素材”误填入卡片。
- **卡片顺序持久化**: 提供上移/下移控制，重新排序后实时更新 `covers` 数组并即时持久化到后端变体记录，刷新或切换版本后顺序不丢失。
- **导出有序卡片 Markdown 清单**: 一键导出包含 YAML 元数据、分卡片尺寸、本地路径及每页专属文案的清单文件 (`ordered-deck-{projectId}.md`)。
- **本地纯净静音 MP4 合成运行器**:
  - 用户可配置每张卡片停留秒数与可选背景音乐路径；留空背景音乐时，调用本地 FFmpeg 自动合成无杂音纯净静音 MP4。
  - 环境中未安装 FFmpeg 时，给出显式环境依赖缺失提示 (`ENOENT: ffmpeg not found`)，不假冒成功。

### 3. 公众号格式化、插图标记映射与双 MIME 剪贴板 (PRD Case 8, 9)
- **HTML 特殊字符实体转义**: 正文生成 HTML 时严格对 `<>&"\'` 进行转义，消除排版崩溃风险。
- **封面与正文插图分离**: 区分第一张头部封面图与正文插图；用户可通过素材角色选择器将素材标记为 `body_image`，并指定排版占位标记（如 `[插图1]`、`[插图2]`）。
- **双 MIME 剪贴板一键复制**: 复制时同时写入 `text/html`（富文本格式，包含行内样式）与 `text/plain`（纯文本后备）；界面显著提示“复制后请在微信公众平台编辑器粘贴，最终发布以平台确认为准”。

### 4. Markdown 导出完整溯源 (PRD Case 40)
- **当前审批版本导出**: `/api/export/markdown` 严格选取当前审批版本 `currentRev` 对应内容，绝不写死 `revisions[0]`。
- **元数据溯源**: Frontmatter 完整保留 `projectId`、`variantId`、`rev`、`sourceIds`、`sourceUrls`、`platform`、`format` 与 `publicationState`。
- **单向只读导出**: 导出操作绝不改变数据库中的发布状态。

### 5. 人工记录发布 CTA 文案规范
- 全站发布按钮文案统一从“确认公开发布”规范化为「记录已发布」/「确认已发布 · 计入今日 KPI」，彻底杜绝“系统会自动发布到外部平台”的误导。

### 6. 对标博主真实性修复 (PRD Case 35, 36, 39)
- **剔除虚假默认值**: 彻底移除新增对标账号时默认填充的 `10万粉` 与 `2000` 互动中位数；未填粉丝数统一入库为 `null` / `未知`。
- **粉丝快照控制与故障保留**: 支持记录粉丝快照（来源：手动输入/TikHub采集/文件导入，精度：精确/近似/未知/采集失败）；当采集失败时保留上一有效快照数值，支持计算双快照有界波动。
- **作品时间线与采样报告**: 界面显式提供时间线与作品采样模态框，明确标注「最早观测样本，非账号注册时间」；支持导入 Gemini 订阅外部研报笔记。
- **历史种子数据标记**: 原生内置的 11 个基准账号明确打标 `isLegacyUnverified: true`，在界面醒目展示“未验证历史数据”，杜绝伪造实时同步。

### 7. 选题雷达真实状态与母项目联动 (PRD Case 27)
- **全状态支持与筛选**: 支持 `to_do`、`in_progress`、`done`、`deferred`、`abandoned` 以及旧状态 `pending`、`accepted`；提供各状态分类标签与即时下拉更新。
- **母项目跳转**: 捕获生成的选题直接保存 `projectId` 并提供「查看关联项目」按钮。
- **状态约束**: 界面明确标注并约束“选题标记为已完成 (done) 仅表示创作阶段结束，绝不计入今日发布 KPI”。

### 8. 今日工作台排期管理与时区对齐 (PRD Case 28)
- **排期日期 (`plannedPublishDate`) 控制**: 变体卡片直接提供可视化排期日期选择控件。
- **细分看板**: 结构化呈现「待发就绪」、「今日应发」、「逾期未发」、「未排期待定」、「制作中草稿」与「全部未发布」。
- **发布隔离**: 单个变体记录发布绝不隐藏项目下的其他平台变体。
- **X 细分拆解**: 显式汇总 short_post、thread（1单元 / N推）、quote、long_article 数量。
- **时区规范**: 每日导出与 KPI 计算强制使用 `Asia/Shanghai` 时区，避免 UTC 零点漂移。

### 9. 设置面板调度器与每日目标配置 (PRD Case 29)
- **TikHub 每日调度配置**: 可视化配置定时启动、检索时间 (时:分)、错峰漏跑策略 (`catch_up` / `skip`)、每日服务商请求上限 (`maxDailyRequests`)、监控平台与检索词。
- **立即测试与调用链跟踪**: 提供「立即触发每日检索」按钮，实时展示请求状态码、覆盖情况与错误日志。
- **每日发布目标配置**: 允许自定义 X 平台 (10-15条) 及其他平台 (1-2条) 的每日目标。

### 10. 回执工作室真实配额与交接指引 (PRD Case 30)
- **动态配额状态**: 回执详情区动态展示 `quotaStatus`（`active` / `paused` / `unknown`），杜绝全量写死为 `paused`。
- **Skill 注册路径与交接目录**: 显示 Skill 本地注册路径、交接任务存储目录，并提供可一键复制的 Antigravity / Codex 对话延续指令。

### 11. 不可变来源版本历史与严格去重 (PRD Case 37)
- **不可变快照版本**: `ArticleSource` 引入 `versions: SourceCaptureVersion[]`，每次对已有来源补充更新正文时自动追加新版本快照，计算 sha256 `contentHash`，记录版本 ID、更新捕获时间与读取状态，保留同一 `sourceId`。
- **安全防误去重**: 严格限制仅当来源 URL 或 canonicalId 非空且全等时才执行匹配，彻底杜绝 `undefined === undefined` 导致无链接素材互相覆盖的缺陷。
- **拆解报告版本追溯**: `ArticleDeconstruction` 关联记录所拆解的具体来源版本 `sourceVersionId` 与 `sourceContentHash`。

### 12. 对话捕获规则 YAML Frontmatter 恢复
- `.agents/rules/workbench-capture.md` 开头恢复标准 YAML frontmatter：
  ```yaml
  ---
  trigger: always_on
  description: Capture only user content ideas into this local workbench; preserve raw input and receipts.
  ---
  ```
- 明确划分排除范围：严禁将代码开发、构建、评审、排错指令当作创作灵感捕获，仅对用户表达的选题灵感、草稿与素材执行入库。
